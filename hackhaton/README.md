# VayOBD — Remote Host Diagnostics

A web app that lets a Vay engineer pick a remote host (vehicle or
telestation) and view its three deployed software versions (vDrive
manifest, vREECU, SEC) pulled live from the host over SSH and
cross-checked against the bundled release manifest. Developer mode
adds a Live diagnostic surface for live CAN / REECU error-queue
inspection.

## End user on Ubuntu 24.04+? Install the .deb

```bash
sudo apt install ./vayobd_*.deb     # see specs/006-deb-package-distribution/quickstart.md
vayobd                              # first launch clones the required repos
                                    # using your existing GitHub credentials
```

The `.deb` bundles the backend, the pre-built UI, and the diagnostic engine.
First launch auto-detects your GitHub credentials (SSH → `gh auth` → system
credential helper) and clones the configuration repos into `~/.cache/vayobd/`.
No `.env`, no virtualenv, no manual `git clone`.

Full walkthrough: **[`specs/006-deb-package-distribution/quickstart.md`](specs/006-deb-package-distribution/quickstart.md)**.

## New developer? Start here

Run the one-time setup script for your OS from the repo root:

| OS | Command |
|----|---------|
| **macOS** | `bash scripts/setup-mac.sh` |
| **Linux** | `bash scripts/setup-linux.sh` |
| **Windows** | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` then `.\scripts\setup-windows.ps1` |

The script installs all dependencies, sets up your SSH key, clones the vehicle
inventory, and generates a `run-dev.sh` / `run-dev.ps1` launcher. It takes
roughly 5 minutes on a fresh machine.

Once done, start the app:

```bash
# macOS / Linux — development (Vite hot-reload, fixture executor)
VAYOBD_DEV_USER=you@vay.io ./run-dev.sh        # → http://localhost:5173

# macOS / Linux — production (built SPA, live SSH executor)
./run-prod.sh                                   # → http://localhost:8000

# Windows — development
$env:VAYOBD_DEV_USER = "you@vay.io"; .\run-dev.ps1

# Windows — production
.\run-prod.ps1
```

Both launchers are generated by the setup script. Settings live in `.env`
(see `.env.example` for all available options).
